# Local supplier review

A fictional grounds-maintenance enquiry demonstrates the path from a document to an
inspectable candidate comparison. All companies and source claims are authored fixtures;
`.example` domains are reserved placeholders.

```bash
make demo
```

Open `outputs/demo/review.html`. No credentials, database server, OAuth or network access
are needed. Expand a supplier to see its listed services, missing evidence, contact state
and qualification documents to request. JSON, CSV and XLSX are linked from the report.

## Inputs and processing

| Input | Role |
| --- | --- |
| [`tender.md`](../../src/vendor_ai_agent/demo_data/tender.md) | Scope, three service requirements and two mandatory documents |
| [`vendors.json`](../../src/vendor_ai_agent/demo_data/vendors.json) | Five supplier records, including one duplicate |

The production document parser and section classifier extract the Markdown sections.
The candidate filter removes duplicates. The demo compares each requested service with
the snapshot's `services` labels, ignoring case and repeated whitespace. It does not infer
synonyms or interpret website prose. The production exporters write the results.

| Supplier | Listed requirements | Evidence gap |
| --- | --- | --- |
| Alder Grounds Cooperative | 3 / 3 | Qualification documents and service area still need review |
| Meadowline Maintenance | 2 / 3 | Hedge trimming not listed |
| Northfield Arborists | 1 / 3 | Mowing and seasonal cleanup not listed; contact missing |
| Cedar Office Supply | 0 / 3 | No requested services listed |

Missing service evidence does not establish that a supplier cannot perform the work.
All candidates retain `match_status=needs_review`. The export's `capability_match_score`
is service-label coverage expressed as a percentage, identified by
`scoring_method=demo_service_coverage`; it is not an LLM assessment or a probability.

## Outputs

- `review.html`: portable comparison and expandable evidence records, with no remote assets.
- [`review.json`](review.json): requirement-level evidence, gaps and follow-up requests.
- [`vendor_matches.json`](vendor_matches.json), plus generated CSV/XLSX: standard export fields.
- Copies of both inputs for inspection alongside the report.

The committed JSON files are generated by `make demo`. To inspect a different local
checklist and structured supplier snapshot with the same field names:

```bash
poetry run tender-vendor-discovery demo \
  --tender-file /path/to/tender.md \
  --vendors-file /path/to/vendors.json \
  --output-dir outputs/custom-review
```

Keep service requirements as bullets under `Technical requirements` and document requests
under `Mandatory requirements`. This explicit local comparison is separate from the live
LLM extraction and matching path described in [Architecture](../../docs/ARCHITECTURE.md).
